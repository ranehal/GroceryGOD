# GroceryGOD // Unified Market Intelligence Engine

GroceryGOD is a high-performance price tracking and comparison matrix for major Bangladeshi grocery stores. It aggregates data from Shwapno, Chaldal, Meena Bazar, and Othoba into a unified dashboard for market analysis.

## 🚀 Architecture: Data Chunking Strategy

To bypass GitHub Pages' 100MB file size limit and optimize browser memory usage, GroceryGOD employs a **Synchronous Manifest-Based Chunking** strategy.

### 1. Aggregation Phase (`aggregator.py`)
- The aggregator calculates price histories and normalized unit prices (e.g., per KG/Ltr).
- Data is deterministically sorted and split into chunks of **20,000 items**.
- **Outputs:**
    - `<store>_manifest.js`: Contains total item count, update timestamp, and the number of chunks.
    - `<store>_data_partX.js`: Contains a subset of the product data assigned to `window.<store>_partX`.

### 2. Uplink Phase (`script.js`)
- The frontend loads store manifests via static `<script>` tags.
- On `DOMContentLoaded`, an asynchronous loader (`loadStoreData`) sequentially fetches each data part.
- **Memory Optimization:** Each part is merged into the master `allProducts` array, and the global chunk variable is immediately deleted (`delete window[...]`) to free up heap space.
- The loader uses dynamic script injection with Promises to ensure all data is synchronized before rendering the UI.

## 🛠 Technical Stack
- **Backend:** Python (SQLite3, JSON, RE for unit normalization)
- **Frontend:** Vanilla JavaScript (ES6+), Chart.js
- **Data Persistence:** SQLite (Trackers), GitHub Pages (Static Serving)

## 🔒 Security & Privacy
- All `.ipynb` (Jupyter Notebooks) are excluded from the repository to prevent accidental leaking of API keys or scraping secrets.
- Market data is sanitized and normalized before being served to the client.
