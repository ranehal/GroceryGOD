🔐 Reverse Engineering & Authentication Mechanism

The FoodiBD Android application (v8.0.3) uses Cloudflare protection and a custom dynamic cryptographic handshake header called sxsrf. Standard HTTP requests receive HTTP 401 Unauthorized unless signed correctly.

1. APK Smali & JADX Analysis

Decompiled Foodi_8.0.3.apk using JADX. Discovered internal security helper class xg.b.c() responsible for header generation.

2. Double-Base64 Encoding

The sxsrf header is calculated as Base64(Base64(raw_token)) where raw_token is extracted from response header cf-ray-status-id-tn.

3. Host Routing Workaround

The API server IP maps to imrs.foodibd.com, but Cloudflare & Spring Boot backends strictly require header Host: api.foodibd.com.

Cryptographic Token Pipeline Code (Python Implementation)

def double_base64_encode(value: str) -> str:
    """Double-base64 encode string (matches APK class xg.b.c)."""
    step1 = base64.b64encode(value.encode("utf-8")).decode("utf-8")
    return base64.b64encode(step1.encode("utf-8")).decode("utf-8")

def extract_cf_ray_from_response(resp) -> Optional[str]:
    """Extract cf-ray-status-id-tn header from response to refresh sxsrf token."""
    cf_raw = resp.headers.get("cf-ray-status-id-tn", "")
    if cf_raw:
        return double_base64_encode(cf_raw)
    return None
